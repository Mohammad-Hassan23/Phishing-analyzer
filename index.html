    How to Think Like a SOC Analyst

    The workflow a defender follows when an alert appears.

    1. Identify the event. What Event ID fired, on which system, at what time?
    2. Understand what happened. Read the event meaning in plain English — don't guess from the number.
    3. Identify the affected user or system. Whose account, which computer?
    4. Determine whether the activity is expected. Was there a change window, a new hire, a patch cycle?
    5. Look for related events. A single event is rarely the whole picture.
    6. Correlate authentication and privilege activity. Failures, successes, new accounts, group changes.
    7. Gather additional evidence. Endpoint telemetry, MFA logs, change tickets, network data.
    8. Decide whether escalation is required. Document your reasoning either way.

    One security event rarely tells the entire story. Analysts build context by correlating multiple events.

    How to export events from Windows Event Viewer

    Keep it simple, and only capture from systems you own or are authorised to monitor.

    1. Press Win+R, type eventvwr.msc, press Enter.
    2. Go to Windows Logs → Security.
    3. Use Filter Current Log… to narrow the events (for example, by Event ID or time range).
    4. Select the events, then right-click → Save Selected Events….
    5. Choose CSV (Comma delimited) and save the file.
    6. Upload that CSV into this tool using the drop zone above.

    Tip: Event Viewer's CSV export only includes the columns shown in the list view and usually omits the detailed Message text (which is where source IP addresses and group names live). For richer data, export with PowerShell instead — see the README for a copy-and-paste command. This tool works with either export and will tell you what it could and could not read.

    Honest limitations

    • CSV exports differ between Windows versions and configurations.
    • Not every event contains a source IP address.
    • Event logging configuration determines what telemetry exists at all.
    • Absence of an event does not prove the activity did not occur.
    • This tool does not replace an EDR, SIEM or a professional SOC platform.
    • Static browser analysis provides limited correlation — it only sees the file you give it.
    • Windows Event IDs alone cannot determine intent.
